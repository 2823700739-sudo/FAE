> [!summary] P4 ↔ C6 通信方式归纳
> - **芯片分工**：ESP32-P4 是应用主控，本身不带 Wi-Fi/Bluetooth 射频；ESP32-C6 作为无线协处理器，负责 2.4 GHz Wi-Fi 6 与 BLE 射频。
> - **默认物理总线**：本表所列带 C6 的微雪 P4 产品通常采用板内 **4-bit SDIO**，包括 `CLK`、`CMD`、`DAT0～DAT3`；不需要另外用杜邦线连接 P4 UART 与 C6 UART。SDIO 是物理链路，ESP-Hosted 是运行在链路上的主从通信方案。
> - **软件链路**：`P4 应用 → esp_wifi_remote / ESP-Hosted Host ⇄ SDIO ⇄ C6 ESP-Hosted Slave → Wi-Fi/BLE`。Wi-Fi 控制命令和网络数据通过 Hosted RPC/数据通道传输；BLE 使用 Hosted HCI/VHCI 通道，必须由主从固件共同启用，不能由“Wi-Fi 可用”推断“BLE 已启用”。
> - **常见参考引脚**：ESP32-P4-Module V1.1 / 乐鑫 P4 Function-EV-Board 的常见映射为 `P4 GPIO18=CLK`、`GPIO19=CMD`、`GPIO14～17=DAT0～3`、`P4 GPIO54→C6 EN/复位`、`C6 GPIO2→P4 GPIO6/唤醒`。**其他产品和硬件版次必须按本型号原理图复核，不可直接套用。** 详见 [[ESP32-P4-Module#板载 C6 通过哪些引脚向 P4 传输 Wi-Fi 与蓝牙|ESP32-P4-Module 的具体接线]]。
> - **UART 的用途**：C6 UART0 主要用于 C6 独立烧录、恢复和日志诊断，不是产品默认的 Wi-Fi AT 主通道；不要把普通 ESP-AT 固件当作配套 ESP-Hosted 从机固件。
> - **固件关系**：P4 与 C6 各自烧录独立固件。P4 端的 `esp_hosted`、`esp_wifi_remote`、SDIO 配置必须与 C6 从机固件配套；仅更新 P4 不会自动更新 C6。恢复或 OTA C6 前还需确认从机固件、分区及升级能力。
> - **硬件注意**：自制板使用 SDIO 时，`CMD` 与 `DAT0～DAT3` 按乐鑫要求配置外部 51 kΩ 上拉，并关注供电、走线、阻抗和时钟质量；成品板已完成板内连接时不要重复飞线。
> - **故障排查顺序**：先核对准确板型/版次和引脚 → 确认 C6 能启动且固件正确 → 检查 P4/C6 Hosted 组件版本与配置 → 查看 SDIO 枚举/Function 1 日志 → 必要时用 C6 UART 只读启动日志，再做降频等对照测试。基础 SDIO 枚举成功不等于 C6 业务固件已正常运行。
> - **资料边界**：乐鑫 ESP-Hosted-MCU 支持 SDIO、SPI 和 UART 等传输，但本表所列微雪 P4+C6 成品默认以板内 SDIO 为准；资料核对不等于所有板型、固件组合均已实测。官方资料：[ESP-Hosted-MCU](https://github.com/espressif/esp-hosted-mcu)、[MCU Host 入门说明](https://github.com/espressif/esp-hosted-mcu/blob/main/docs/getting-started-mcu.md)、[乐鑫 SDIO FAQ](https://docs.espressif.com/projects/esp-faq/en/latest/software-framework/peripherals/sdio.html)。
