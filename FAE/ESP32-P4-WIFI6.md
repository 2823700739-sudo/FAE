# ESP32-P4-WIFI6

### 整板应使用 5V 还是 3.3V 供电
- **客户问题/现象**：询问整板供电电压。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：整板电源轨由 5V 输入后转换为 3.3V；GPIO 逻辑仍为 3.3V。
- **回复内容（解决方法）**：通过 Type-C 或排针 5V/GND 输入稳定 5V，不要把 5V 接到 3V3 或普通 GPIO。外部信号必须按 3.3V 逻辑电平处理。
- **相关报错/日志**：无。

### 未接 USB 时排针 5V 和 OTG VBUS 都为 0V
- **客户问题/现象**：只有插入 USB TO UART 后排针 5V 才有电压，怀疑故障。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：排针 5V 是整板电源轨，不是 P4 自行产生的常供输出；没有任何 5V 输入时测得 0V 属正常。
- **回复内容（解决方法）**：插 USB TO UART 后再测 5V-GND 和 OTG VBUS-GND，均应接近 5V。若 USB 输入端有 5V但排针/OTG仍为 0V，才检查线材、电源灯和 5V 电源路径。不要把外部 5V接普通 GPIO。
- **相关报错/日志**：无。

### 能否接 ML307R-DL 4G 模块
- **客户问题/现象**：询问 4G 模块是否支持、升级 IDF 是否可直接使用。
- **涉及产品/型号**：ESP32-P4-WIFI6、ML307R-DL。
- **根因**：板卡有 UART/USB 通用接口，但微雪没有 ML307R-DL 官方示例，`esp_modem` 也无现成该型号配置。
- **回复内容（解决方法）**：只能回复“硬件接口上可尝试，需要自行适配”，不能说即插即用。优先经 UART 测试 AT；裸模组需 3.4～4.5V独立供电且 UART 为 1.8V，不能直接接 3.3V GPIO。使用模组内置 MQTT/HTTP 可走 AT；若要系统网络接口则需移植 PPP/自定义 `esp_modem`。
- **相关报错/日志**：先确认 115200 下发送 `AT` 返回 `OK`。

### 是否有 IMX708 官方适配方案
- **客户问题/现象**：询问 P4-WIFI6 能否直接使用 IMX708。
- **涉及产品/型号**：ESP32-P4-WIFI6、IMX708。
- **根因**：有 2-lane MIPI-CSI 硬件，但官方驱动/示例主要适配 OV5647，当前官方传感器清单没有 IMX708。
- **回复内容（解决方法）**：⚠️ 官方无现成方案，不能承诺支持。需要自行开发初始化寄存器、供电与 MIPI 时序、ISP 参数和自动对焦；优先使用官方适配 OV5647。第三方驱动只能作为样机验证。
- **相关报错/日志**：无。

### 能否适配 IMX219-77 Camera
- **客户问题/现象**：询问 ESP32-P4-WIFI6 能否连接并使用 IMX219-77 摄像头。
- **涉及产品/型号**：ESP32-P4-WIFI6、IMX219-77 Camera。
- **根因**：板卡与摄像头都使用 2-lane MIPI-CSI，硬件协议具备适配条件；但微雪官方示例默认适配 OV5647，乐鑫官方 `esp_cam_sensor` 支持列表也没有 IMX219。
- **回复内容（解决方法）**：⚠️ 不能按即插即用承诺。必须先核对 FPC 针数、间距、触点方向、供电和脚位，再在 ESP-IDF 中集成第三方 IMX219 驱动并修改板级配置。已有第三方方案报告约 1640×1232、28fps，但不是微雪官方适配，需要样机验证。ESP32-P4 ISP 实用处理上限为 1920×1080，不能直接按树莓派方案输出完整 3280×2464 ISP 图像；需要开箱即用时仍优先使用 OV5647。
- **相关报错/日志**：🔍 第三方驱动兼容性、实际帧率与图像质量需在本板和目标摄像头批次上验证。

### 能否连接 OC2033 双通道 MIPI-CSI 传感器

- **相关报错/日志**：无。

### 摄像头 800×640@50fps 接 1024×600 DSI 屏能跑多少帧
- **客户问题/现象**：询问只做摄像头取流、PPA转换和显示时的预期帧率。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：摄像头输入上限 50fps，屏幕时序 60Hz；实际受模式、PPA、缓冲和附加业务影响。
- **回复内容（解决方法）**：⚠️ 可按 40～50fps 估计，优化后可能接近 50fps；同时运行复杂 LVGL、编码或网络时可能降到约 25～40fps。需先确认驱动确实支持 800×640@50fps；宽高比不同还要选择裁剪、拉伸或留边，最终以实测为准。
- **相关报错/日志**：官方示例默认常见为 OV5647 RAW8 `800×1280@50fps`，不要误写成 800×640。

### 能否实现 WebRTC
- **客户问题/现象**：希望做低延迟视频监控、门铃或双向通话。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：硬件具备 H.264 编码、CSI、PSRAM和 C6 Wi-Fi；仍需板级、媒体管线和信令适配。
- **回复内容（解决方法）**：可基于乐鑫 `esp-webrtc-solution` 移植，建议先做 720p 15～30fps、H.264、单路上行，音频先 G.711 再评估 Opus/AEC。公网通常需 STUN/TURN，多人观看建议通过 SFU。官方 `simple_video_server` 可先验证摄像头、编码和网络。
- **相关报错/日志**：不是烧录官方例程即可完成；双向音频和公网连通是主要开发量。

### P4 与 C6 的 SDIO 初始化失败，Wi-Fi 不可用
- **客户问题/现象**：官方视频服务器或 Wi-Fi 工程在网络初始化阶段超时；自写程序跳过 C6检查后无 Wi-Fi。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：P4 自身无 Wi-Fi，C6 未响应 SDIO；常见原因是 C6 未运行匹配的 ESP-Hosted Slave、主从版本不匹配、C6 在下载/复位状态、旧 sdkconfig 或硬件信号问题。
- **回复内容（解决方法）**：先用相同环境烧官方 `10_wifistation`，完全断电重启并确认 C6 IO9 未被拉低；核对 `esp_wifi_remote`/`esp_hosted` 与 C6固件配套，必要时读取 C6 UART。官方示例仍超时时再检查 3.3V、EN、SDIO上拉和焊接。摄像头 PID 读取失败是另一条问题，应断电检查排线、供电与传感器型号。
- **相关报错/日志**：`sdio_card_fn_init failed`、`sdmmc_io_read_byte ... returned 0x107`、`Not able to connect with ESP-Hosted slave device`。

### 板载 Type-C 看不到 JTAG，能否不用 JTAG 做断点调试
- **客户问题/现象**：设备管理器只有串口，没有 JTAG；希望断点调试。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：板载 Type-C 经 CH343P 只提供 UART；内置 USB-JTAG 的 GPIO24/25只引到 40Pin。
- **回复内容（解决方法）**：JTAG 需把 GPIO24(D-)/GPIO25(D+)和 GND 接到 USB，安装 Espressif驱动后用 `board/esp32p4-builtin.cfg`。不接 JTAG 时可启用运行时 GDB Stub，经板载串口中断、设断点和单步，但不适合 Bootloader、严重死机和复杂多核实时问题。目标芯片必须供电，“断电调试”不可行。
- **相关报错/日志**：`CONFIG_ESP_SYSTEM_GDBSTUB_RUNTIME`。

### C6 使用 AT 固件还是 ESP-Hosted 固件
- **客户问题/现象**：询问板载 ESP32-C6 是否运行 AT 固件，以及 P4 与 C6 的通信方式。
- **涉及产品/型号**：ESP32-P4-WIFI6。
- **根因**：该产品采用 P4 主机加 C6 无线协处理器架构，主通信通道为 SDIO，不是 UART AT 指令。
- **回复内容（解决方法）**：P4 侧运行 `esp_hosted` 与 `esp_wifi_remote`，C6 侧运行匹配版本的 ESP-Hosted Slave/network_adapter 固件。不要把 C6 改刷为普通 ESP-AT，否则官方 Wi-Fi 示例无法建立 Hosted SDIO 通信；恢复或升级时应烧录与 P4 端版本匹配的 C6 Slave 固件。
- **相关报错/日志**：无。

### 高速 SD 卡只能读不能写，低速卡正常
- **客户问题/现象**：高速或大容量 SD 卡无法写入，慢速卡读写正常；进一步询问 SDMMC 时序要求。
- **涉及产品/型号**：ESP32-P4-WIFI6、SDMMC。
- **根因**：⚠️ 尚无实测定论；更可能是高速卡暴露了 SDMMC 信号完整性、上拉、卡座接触或 3.3V 供电裕量问题，也需排除 exFAT、坏卡和扩容卡。写操作电流更大，通常比读取更容易触发故障。
- **回复内容（解决方法）**：先固定为 20MHz、1-bit 测试，再逐步测试 20MHz/4-bit、40MHz/1-bit、40MHz/4-bit。CMD、DAT0～DAT3 应有约 10kΩ 外部上拉，CLK 不加上拉且走线应短；在卡座端测 CLK、CMD、DAT0 与 3.3V。备份后改 FAT32，并用 H2testw/F3 及另一张真品卡交叉验证。若只有写失败，优先查写入瞬间 3.3V 跌落、CLK 过冲/振铃和 DAT1～DAT3 连接。
- **相关报错/日志**：需收集 `ESP_ERR_TIMEOUT`、`FR_DISK_ERR`、`FR_WRITE_PROTECTED`、`FR_NO_FILESYSTEM` 等实际错误。

### Wi-Fi 视频卡顿、方向敏感且吞吐约 3Mbps
- **客户问题/现象**：视频一动就卡死，板子需要朝向路由器特定方向，实测速率约 3Mbps；客户进一步询问 C6 能否加外置天线。
- **涉及产品/型号**：ESP32-P4-WIFI6、ESP32-C6-MINI-1-N4。
- **根因**：⚠️ 不能仅凭视频表现判定硬件或天线故障；可能涉及视频编码、缓存、阻塞发送、Wi-Fi 省电、ESP-Hosted 配置、天线遮挡或无线环境。
- **回复内容（解决方法）**：先用未修改的官方程序和 `iperf` 测试 TCP 双向速率；在 1～2 米、2.4GHz、无遮挡条件下记录 RSSI、路由器/信道、完整日志和测试结果，并更换路由器交叉验证。官方示例也持续异常时再按硬件问题处理；仅自研视频程序异常则属于二次开发，应检查码率、TCP/UDP 缓冲、阻塞发送、省电和组件版本。现板使用 PCB 天线且没有 IPEX/U.FL 和射频切换位，不能直接加天线；改用 C6-MINI-1U 需要改板和重新验证射频，属于硬件二次开发。
- **相关报错/日志**：⚠️ 约 30Mbps 仅是特定优化条件下的参考测试值，不是产品承诺。

### 同时启用主要外设时如何分配两组 UART
- **客户问题/现象**：在 DSI 屏、CSI 摄像头、C6 Wi-Fi、板载音频和 MicroSD 同时使用时，需要一组 UART 接 4G 模块，另一组接马达控制板。
- **涉及产品/型号**：ESP32-P4-WIFI6、ESP32-P4 UART1～UART4。
- **根因**：除 UART0 被 CH343P 调试接口占用外，UART1～UART4 可通过 GPIO Matrix 映射到空闲 GPIO；实际可用性取决于板载外设、USB/JTAG、启动脚和电源域占用。
- **回复内容（解决方法）**：推荐 4G 模块使用 UART1：P4 TX=GPIO30、RX=GPIO31；马达控制板使用 UART2：P4 TX=GPIO28、RX=GPIO29。4G 若需要硬件流控，可评估 RTS=GPIO32、CTS=GPIO33。应避开 GPIO37/38（UART0/启动相关）、GPIO34～38（启动配置）、GPIO7/8（板级 I2C）、GPIO9～13及53（音频）、GPIO14～19、6、54（C6 SDIO/控制）、GPIO39～45（MicroSD）、GPIO24/25（USB Serial/JTAG）；GPIO2～5涉及可选 JTAG，GPIO46～48依赖 VDD_IO4 供电域，均不作为首选。所有 UART 为 3.3V 逻辑，4G 模块或马达板为 1.8V/5V 时必须电平转换；4G 应独立足额供电并与开发板共地。
- **相关报错/日志**：🔍 推荐映射基于当前原理图和 40Pin 定义，量产前应按实际硬件版本再次核对引脚占用。

### GPIO45 控制 TF 卡供电，删除文件后旧文件重新出现
- **客户问题/现象**：询问 GPIO45 的 TF 卡上电控制用途；将 GPIO45 拉低后，之前删除或格式化的录像文件在断电重启后重新出现。
- **涉及产品/型号**：ESP32-P4-WIFI6、MicroSD/TF 卡、GPIO45。
- **根因**：GPIO45 控制高边 P-MOS：低电平给 TF 卡上电，高电平断电；R22 10kΩ 下拉使 TF 卡在复位和未配置 GPIO 时默认上电。⚠️ 拉低本身不应恢复旧文件；更可能是 TF 卡进入只读故障状态、文件系统损坏、录像结束时未 `flush/fclose` 和卸载，或 GPIO 初始化毛刺造成瞬时掉电。
- **回复内容（解决方法）**：没有低功耗需求时先不要主动控制 GPIO45，让硬件保持默认上电。必须初始化时，先执行 `gpio_set_level(GPIO_NUM_45, 0)`，再设为输出并等待约 100ms，录像期间始终保持低电平。断电顺序应为“停止录像→刷新并关闭文件→卸载 FAT 文件系统→GPIO45 拉高断电”，随后把 CLK/CMD/D0～D3 设为输入或低电平，避免信号脚反向供电。把卡放到电脑完整格式化并安全弹出；若旧文件仍恢复，基本可判定卡本身异常，应更换可靠真品卡。必要时用示波器检查配置 GPIO45 瞬间 TF 卡 VDD 是否跌落。
- **相关报错/日志**：无；“删除或格式化后重启旧文件恢复”不是 GPIO45 正常功能。

### P4 芯片从 v1 换成 v3 时需补焊 R37
- **客户问题/现象**：询问 ESP32-P4 从 v1.x 更换为 v3.x 时需要在哪里加焊电阻，以及该电阻的作用。
- **涉及产品/型号**：ESP32-P4-WIFI6、ESP32-P4 rev v1.x/v3.x。
- **根因**：P4 v1.0/v1.3 的封装 54 脚为 NC，v3.0 以后改为 `VDD_HP_1`。本板预留 R37，把第 54 脚连接到约 1.2V 的 `ESP_VDD_HP` 核心电源轨。
- **回复内容（解决方法）**：更换 v3 芯片时在 R37 焊盘安装 0Ω电阻，使 `VDD_HP_1 → R37 → ESP_VDD_HP`。该电阻是版本兼容电源跳线，不是限流、分压或上拉电阻，不可接到 3.3V。不补焊可能导致无法启动、随机重启或运行不稳定。量产改版还需按乐鑫 v3 参考设计复核 DCDC 反馈、反馈电容和 USB_DP 外围，不能只补 R37。
- **相关报错/日志**：🔍 位号与连接关系基于当前公开原理图；焊接前应核对实际 PCB 版本。

### 默认蓝牙名称是什么，手机为什么搜索不到
- **客户问题/现象**：询问 ESP32-P4-WIFI6 的蓝牙名称，并希望通过手机系统蓝牙列表查找设备。
- **涉及产品/型号**：ESP32-P4-WIFI6、ESP32-C6、BLE。
- **根因**：开发板没有固定蓝牙名称；P4 本身无蓝牙射频，BLE由板载C6提供，广播名称由当前烧录程序设置。只上电但固件没有启动BLE广播时，不会出现任何蓝牙设备；BLE设备也未必显示在手机系统的普通经典蓝牙配对页面。
- **回复内容（解决方法）**：先确认P4与C6烧录的是支持Hosted BLE的配套固件，再在程序中设置BLE设备名，例如使用 `esp_ble_gap_set_device_name()` 或配网组件的 `service_name`。不要默认按“ESP32-P4-WIFI6”搜索，建议使用 nRF Connect 等BLE扫描工具查看广播；如果没有广播，应检查C6固件能力、P4端ESP-Hosted/NimBLE配置和两端版本是否匹配。
- **相关报错/日志**：无固定出厂广播名；仅运行普通 Wi-Fi 示例时可能完全没有 BLE 广播。
