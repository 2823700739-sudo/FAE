- **回复内容（解决方法）**：可回复“采用2A档USB电源开关，实际持续电流还受输入源余量、整板屏幕/Wi-Fi/音频/充电负载、接插件、走线压降和散热影响”。5V/2A适配器供整板时不能再保证外设2A；电池供电还受升压和保护能力限制。按目标工况逐步带载测电压、温升和稳定性，不由480Mbps速率推算电流。[板图](https://www.waveshare.net/w/upload/e/e3/ESP32-P4-WIFI6-Touch-LCD-7B.pdf)、[器件手册](https://www.dioo.com/uploads/product/20200827/6a2aba7e930a1fcc45a7653122974d97.pdf)。

### C6 UART、IO9 烧录方式与板载以太网
- **客户问题/现象**：询问板载 C6 是否可作为 TTL AT 模块、能否由软件把 C6_IO9 拉低进入下载模式、UART 速率上限，以及 P4 所谓“内置网口”能否直接连接网线。
- **涉及产品/型号**：ESP32-P4-WIFI6-Touch-LCD-7B。
- **根因**：C6 默认通过 SDIO 运行 ESP-Hosted，不是 UART AT 模块。C6_IO9 是上电/复位时采样的启动配置脚，7B 板没有从 P4 到 C6_IO9 的软件控制通路；应用启动后再拉低也已错过采样时刻。P4 芯片虽有 Ethernet MAC，但本开发板没有 Ethernet PHY 和 RJ45。
- **回复内容（解决方法）**：默认硬件上给 C6 进入 ROM 下载模式必须在断电后物理短接 `C6_IO9-GND`，用 3.3V TTL 连接 C6 UART，按住 P4 BOOT 后上电，整个烧录过程保持短接；成功后断电、拆线再上电。P4 只能控制 C6 复位，不能软件控制 IO9。若 C6 当前固件仍能运行，可评估经 P4/SDIO 做 Slave OTA，但这不是救砖通道。C6 UART 主要用于固件烧录和调试，不应改刷普通 AT 固件；速率从 115200～921600 实测。P4 的 Ethernet MAC 仍需外置 PHY、变压器和 RJ45，7B 无完整板载通路，稳定有线网络应改选带网口型号。
  复位补充：GPIO54→R33(0Ω)→C6 EN(模组8脚)，GPIO6经R31接C6 IO2，不是复位。飞线后才恢复时，先断电测R33/走线和实装，再看EN低脉冲及3.3V；GPIO47飞线不能与GPIO54争用EN，且需核对LDO4域电压。H4为1=IO9、2=GND、3=C6 RX、4=C6 TX，IO8应高、IO9低。以115200、手动下载比较no-reset及--no-stub，前者跳自动复位、后者不上传Stub，含义不同；若0x05确为ROM状态则是消息格式错误，须完整命令/日志确认。C6 bootloader通常0x0、应用按实际分区。SDIO不稳时核对CLK/CMD两端不同编号和DAT1中断，再评估两端匹配低频/1bit配置。921600、8N1单向理论92160B/s，20～44KB/s应用吞吐不足以证明硬件异常。以上为图纸/协议排查，未确认批次缺陷或RMA。
  通信架构补充（2026-10-31）：正常架构为 `P4 应用 → esp_wifi_remote / ESP-Hosted Host ⇄ 板内 SDIO ⇄ ESP32-C6 ESP-Hosted Slave → 无线网络`。SDIO 的 CLK、CMD、DAT 信号已由板内走线连接，使用对应官方固件不需要再用杜邦线把 P4 UART 与 C6 UART 相连。P4 编写业务并经适配层使用 `esp_wifi_init()`、`esp_wifi_set_config()`、`esp_wifi_start()`、`esp_wifi_connect()` 等 API；C6 负责无线射频和从机业务。若启用 BLE，P4 的 Host 与 C6 Controller 还需匹配的 Hosted HCI/VHCI 支持，不能由 Wi-Fi 正常推断 BLE 已开启。若板上引出 C6 UART，通常用于独立烧录/日志维护，并非该产品默认的 Wi-Fi AT 主通道。保持本型号 P4 端依赖、SDIO 配置与 C6 从机固件配套，主从版本号数值不必相同；不要改刷普通 ESP-AT，也不要把 P4 镜像写给 C6。已有兼容从机固件时，日常只更新 P4 应用；仅烧 P4 不会自动更新从机。 支持2.4 GHz Wi-Fi 6与BLE，不把Wi-Fi 6等同5 GHz，也不把BLE等同经典蓝牙音频。 [本型号官方资料](https://docs.waveshare.net/ESP32-P4-WIFI6-Touch-LCD-7B/)，本次板内连接依据本地 Docs_zh 的 `ESP32-P4-WIFI6-Touch-LCD-7B/Product-Overview.md`。
- **相关报错/日志**：出现 TTL COM 端口不能证明 C6 已进入下载模式；应以 esptool 成功识别 ESP32-C6 为准。

### 二次开发、17 个扩展 GPIO、烧录恢复和示例源码
- **客户问题/现象**：询问照片中标注的 IO 是否都能自定义，以及是否支持完整二次开发、烧录失败会不会锁死、示例是否提供源码。
- **涉及产品/型号**：ESP32-P4-WIFI6-Touch-LCD-7B。
- **根因**：支持二次开发，但板载外设占用部分 GPIO，芯片全部引脚并未全部物理引出；普通烧录失败与安全 eFuse 锁定是两回事。
- **回复内容（解决方法）**：照片中的 `GPIO2、3、4、5、28、29、30、31、34、36、46～52` 共 17 个独立 GPIO 均可编程；IO4 在两个接口重复引出，仍是同一个 GPIO。可映射数字输入输出、中断、UART、I2C、SPI、PWM 等，但 ADC 等特殊功能需按芯片引脚能力确认。GPIO34/36 是启动配置脚，复位后可正常使用，但上电/复位期间不能被外部电路强拉到错误电平；GPIO36 板上已有上拉。全部使用 3.3V 逻辑，不可直接输入 5V。推荐 ESP-IDF，也提供 Arduino 示例；复用前查原理图避免板载外设冲突。普通烧录中断或错误固件不会锁死，可按住 BOOT 后复位进入下载模式并重烧；只有主动配置安全相关 eFuse 才会限制恢复。官方示例覆盖主要功能，但不代表每类应用都有完整成品代码。
- **相关报错/日志**：IO4 重复引出不增加独立 GPIO 数量；GPIO34/36 上电电平错误可能影响启动。

### Type-C 如何给整板供电，5V 入口和纹波有什么要求
- **客户问题/现象**：询问两个 Type-C 的供电控制方式、可用 5V 入口，以及“纹波”含义和允许范围。
- **涉及产品/型号**：ESP32-P4-WIFI6-Touch-LCD-7B。
- **根因**：两个 Type-C 的 CC1/CC2 使用 5.1kΩ 下拉，未见 PD 协议控制器，应按普通 5V 电源入口使用；板载 POWER 开关控制 Type-C 后面的整板电源通路。官方资料未给出最大允许纹波。纹波是直流电压上叠加的快速波动，过大可能引起重启、闪屏、触摸异常、USB 掉线或音频噪声。
- **回复内容（解决方法）**：`USB` Type-C 用于供电、USB设备功能与烧录/调试；`USB TO UART` Type-C 用于供电、串口烧录和日志。只输入稳定 5V，不可直接送 9V/12V；建议 5V/2A 以上，外设较多时可用 5V/3A。不要同时连接不同电源。工程上建议在满背光、Wi-Fi/音频负载下用短地线示波器并限制约 20MHz 带宽测量，板端电压尽量保持约 4.75～5.25V，纹波尽量控制在 100mV 峰峰值以内；该数值是保守建议，不是官方保证值。CAN/RS485 的 PH2.0 5V脚不是官方专用电源入口；BAT 只能接单节 3.7V 锂电池。
- **相关报错/日志**：⚠️ 官方没有公布明确的最大纹波指标；长线压降或负载突变造成的瞬时跌落容易被误认为纹波。

### 是否有官方组态屏案例
- **客户问题/现象**：询问是否提供拖拽组态界面并可直接连接PLC的官方完整案例。

### Type-C 与电池同时供电，拔掉 Type-C 为什么重启
- **客户问题/现象**：同时连接Type-C和锂电池时，拔掉Type-C后开发板重启，希望确认具体责任电路。
- **涉及产品/型号**：ESP32-P4-WIFI6-Touch-LCD-7B、SCT12A0、ETA6098。
- **根因**：该板不是无缝Power-Path/UPS设计。USB存在时，`VCC_5V → R67 → Q5` 把电池升压U17的EN拉低；拔掉USB后VCC_5V先下降，Q5才释放EN，U17再经C166=47nF软启动，约需11.3ms后才建立Boost_5V并经Q7回到VCC_5V。现有约67µF输出电容无法在屏幕、P4与Wi-Fi负载下维持空档，导致Core_5V/ESP_3V3跌落。ETA6098只负责充电，没有独立SYS Power-Path。
- **回复内容（解决方法）**：若单独USB和单独电池都稳定，仅插拔瞬间重启，则优先按电源架构特性处理。用示波器同时测VCC_5V、U17 EN、Boost_5V和Core_5V/ESP_3V3，并触发在Type-C拔出沿；若电源轨不跌落再查CH343P DTR/RTS是否给ESP_EN复位脉冲。可靠改版应使用真正的Power-Path/电源MUX，或让升压热备并通过理想二极管无缝OR；不要简单拆Q5，也不建议只并大电容，以免争流、循环供电和浪涌。
- **相关报错/日志**：软启动估算 `tSS = 47nF × 1.2V / 5µA ≈ 11.3ms`；⚠️ 最终应以VCC_5V/Core_5V实测跌落和复位日志确认。
