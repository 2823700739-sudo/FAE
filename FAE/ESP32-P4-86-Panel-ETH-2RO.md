## ⚠️ 产品参数 / 规格（优先查看）

### P4 与板载 C6 如何连接和通信，是否需要另接串口
- **客户问题/现象**：询问本产品P4和无线芯片之间的连接、通信方式，以及是否需要外接串口/AT固件。
- **涉及产品/型号**：ESP32-P4-86-Panel-ETH-2RO、ESP32-C6、ESP-Hosted。
- **根因**：P4本身不带Wi-Fi/Bluetooth射频；本产品的板载ESP32-C6作为无线协处理器，通过SDIO连接P4，软件使用ESP-Hosted；SDIO物理总线与其上的RPC/网络数据不是同一概念。
- **回复内容（解决方法）**：正常架构为 `P4 应用 → esp_wifi_remote / ESP-Hosted Host ⇄ 板内 SDIO ⇄ ESP32-C6 ESP-Hosted Slave → 无线网络`。SDIO 的 CLK、CMD、DAT 信号已由板内走线连接，使用对应官方固件不需要再用杜邦线把 P4 UART 与 C6 UART 相连。P4 编写业务并经适配层使用 `esp_wifi_init()`、`esp_wifi_set_config()`、`esp_wifi_start()`、`esp_wifi_connect()` 等 API；C6 负责无线射频和从机业务。若启用 BLE，P4 的 Host 与 C6 Controller 还需匹配的 Hosted HCI/VHCI 支持，不能由 Wi-Fi 正常推断 BLE 已开启。若板上引出 C6 UART，通常用于独立烧录/日志维护，并非该产品默认的 Wi-Fi AT 主通道。保持本型号 P4 端依赖、SDIO 配置与 C6 从机固件配套，主从版本号数值不必相同；不要改刷普通 ESP-AT，也不要把 P4 镜像写给 C6。已有兼容从机固件时，日常只更新 P4 应用；仅烧 P4 不会自动更新从机。 支持2.4 GHz Wi-Fi 6与BLE，不把Wi-Fi 6等同5 GHz，也不把BLE等同经典蓝牙音频。
- **相关报错/日志**：🔍 本次为产品资料/软件架构核对，未逐板实测；SDIO具体引脚及下载接口按本型号实板/原理图，不套用其他P4板。[本型号官方资料](https://docs.waveshare.net/ESP32-P4-WIFI6-Touch-LCD-4B/)，本次板内连接依据本地 Docs_zh 的 `ESP32-P4-WIFI6-Touch-LCD-4B/Product-Overview.md`。核对日期：2026-10-31。

### 是否属于工业级 ESP32-P4 板卡
- **客户问题/现象**：希望选择工业级P4产品。
- **涉及产品/型号**：ESP32-P4-86-Panel-ETH-2RO。
- **根因**：该型号有DC 6～30V、RS485、以太网、两路继电器、隔离和86盒结构，偏工控设计；但公开资料未提供完整整机宽温、EMC、浪涌、振动或IP等级报告。
- **回复内容（解决方法）**：⚠️ 可作为室内控制柜、温和环境的优先样机候选，但不能仅凭“适合工业控制”认定为完整工业级。量产前向厂家索取整板温度、EMC/ESD/EFT/浪涌、环境机械测试、固定BOM/PCN/EOL与可靠性报告，并按实际现场验证。
- **相关报错/日志**：无。

### 两路继电器能否用语音控制
- **客户问题/现象**：希望语音助手控制板载继电器。
- **涉及产品/型号**：ESP32-P4-86-Panel-ETH-2RO。
- **根因**：硬件具备两路隔离继电器，但普通小智/语音固件不一定自带继电器工具调用。
- **回复内容（解决方法）**：硬件可行，历史记录中两路控制脚为GPIO32、GPIO46。需在固件增加语音命令/AI工具调用，或接入Home Assistant/ESPHome。控制市电时核对触点额定，做好保险、绝缘和封闭外壳，先用低压负载测试。
- **相关报错/日志**：无。

### 能否用板载 C6 实现 Zigbee
- **客户问题/现象**：客户询问面板支持Zigbee与否。
- **涉及产品/型号**：ESP32-P4-86-Panel-ETH-2RO、板载ESP32-C6；具体无线模组后缀按板次复核。
- **根因**：C6具备IEEE802.15.4/Zigbee射频开发基础，而出厂ESP-Hosted Wi-Fi/BLE从机不等于运行Zigbee应用。
- **回复内容（解决方法）**：原问答称硬件可评估，但未找到本板即用Zigbee固件/示例。需明确协调器/路由器/终端角色，开发匹配C6 Zigbee程序及与P4通信；重刷C6前评估原Hosted Wi-Fi/BLE功能如何保留，不认为同一链路自动携带任意协议。不能由芯片支持推成开箱接入任意Zigbee设备或承诺所有无线功能并发。
- **相关报错/日志**：🔍 开发能力说明，未本板Zigbee入网/协调器验证。来源：2026-11-05《确认是否支持 ZigBee》，本次读取完整原问答；除另注外无本板实测。

## 其他问题

### ESP-Hosted SDIO 通信超时并进入不可恢复状态
- **客户问题/现象**：P4 与板载 C6 长时间运行后出现 `0x107`、SDIO 写入超时和 `Unrecoverable host sdio state`；之后客户把 C6 改刷为通用 2.12.11 Slave，Wi-Fi 立即不可用。
- **涉及产品/型号**：ESP32-P4-86-Panel-ETH-2RO、ESP32-P4、ESP32-C6、ESP-Hosted。
- **根因**：出厂组合已确认是 P4 端 `esp_hosted 2.12.11` 加 C6 Slave FW `0.0.6`，两者版本号含义和编号体系不同，数值不相同不能直接判为不兼容。客户改刷的通用 2.12.11 C6 示例可能改变了 SDIO模式、队列、速率或板级配置，因此“刷后立即无 Wi-Fi”与原先“运行约两天后 SDIO 超时”应分开分析。⚠️ 原始长期运行故障仍可能来自 ESP-Hosted 恢复路径、SDIO 传输或硬件，尚未确诊。
- **回复内容（解决方法）**：先恢复厂家提供的 C6 出厂 `0.0.6` 二进制文件，并配合原厂 P4 固件复测，不要仅凭版本数字把 C6 升级为 2.12.11。通过 C6 的 3.3V UART、115200 波特率抓上电日志，确认 `ESP-Hosted-MCU Slave FW version :: 0.0.6`；P4 的 2.12.11 从 `dependencies.lock` 核对。提供的 C6 源码目录自身声明为 1.4.7，重新编译后理论上会显示 1.4.7，不能视为出厂 0.0.6 的精确源码快照，因此恢复时优先使用原厂 `.bin`。恢复后若 Wi-Fi 正常，再单独进行 48～72 小时压力测试；仍出现原始超时时，再查 ESP-Hosted 恢复机制、3.3V、C6 EN、SDIO 上拉/焊接和硬件个体。
- **相关报错/日志**：`ESP_ERR_TIMEOUT (0x107)`、`Unrecoverable host sdio state`、出厂标识 `ESP-Hosted-MCU Slave FW version :: 0.0.6`；C6 源码包 `idf_component.yml` 标记为 `1.4.7`。
